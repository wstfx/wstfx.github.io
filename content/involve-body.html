01 / The product question

Keep both sides of a lesson connected.

A lesson contains more than material to present. A teacher prepares an explanation, opens a question, waits for responses, and decides what to discuss next. Students need to know where they are in that sequence and what they can do. InVolve brings preparation, classroom activities, and response review into one teaching workspace.

My contribution

I lead the frontend, UI, and interaction design. I work on the lesson editor, question organization, student preview, classroom controls, and the transitions that connect them, using Vue and TypeScript.

A shared implementation

My collaborator develops the backend. I connect the interface to its APIs and classroom events, translating lesson and question states into visible actions and feedback.

02 / Information architecture

Separate the teacher’s task from the student’s stage.

An early version used a Pre-Class / On-Class toggle. The later design separates two questions: what is the teacher doing, and which part of the lesson is being designed? Design / Teach / Assess organizes the teacher’s work; Prepare / Engage / Practice organizes the learning material.

THE TEACHER’S WORK

Design

Compose the lesson.

Teach

Guide the classroom.

Assess

Manage practice and review.

THE STUDENT’S LEARNING STAGES

Prepare

Before the lesson.

Engage

During the lesson.

Practice

After the lesson.

This makes it possible to design an in-class activity before the class begins, or prepare follow-up practice without treating it as a separate document. Students see the same three learning stages, without the teacher’s editing and distribution controls.

03 / The original application

Compose once. See it from both sides.

The lesson editor combines headings, explanations, images, files, and questions in a single ordered sequence. An outline provides navigation through longer lessons. Student preview lets a teacher inspect how that sequence reads without the editing controls; Teach brings the questions and classroom actions to the foreground.

These are captures of the original Vue application using my saved course content in a local preview. They show the interface and material; live responses, backend operation, and student outcomes were not evaluated in this preview.

04 / State and feedback

Make the next action understandable.

A question can exist in a lesson without being ready for students. It can be open for responses, or closed while remaining useful for discussion. I worked on making those distinctions visible, rather than letting a change of state remove the student’s context.

01 / PREPARE

Draft

Teachers can organize questions before releasing them. Draft questions stay out of the student question view.

02 / PARTICIPATE

Open

The interface exposes the question’s availability and timing. Access rules distinguish always-open exercises from questions opened for distribution.

03 / DISCUSS

Closed

For questions that open on distribution, collection locks further changes and sharing while preserving the answer area and access to results.

Question sets and ordered content keep related activities together. Statistics and answer-sharing views provide places to inspect what happened, with submission progress kept distinct from revealed results.

05 / A real teaching context

Use the tool from the teacher’s chair.

I created and taught an introduction to coding with AI agents for people with no previous programming experience, using InVolve. This joined two responsibilities: building the classroom interface and shaping the material that would move through it.

The saved lesson starts with a familiar activity—cooking—to explain task planning, decomposition, data, and processing. It then connects reading, writing, running, and debugging code with the workflow of an AI coding agent.

From explanation to a task.

One exercise asks students to plan a university exercise-habits report: establish the goal, break down the investigation, obtain data, and decide how to analyze it. The question makes the preceding explanation something to work with.

06 / Frontend craft

Keep the interface steady as the task changes.

Much of my frontend work is in the transitions between states: preserving scroll position when changing learning stages, keeping question groups organized, and moving between editing and student preview. Short press feedback and paced mode transitions make controls respond visibly without moving the user to a different lesson.

The work has produced an original teaching interface and a course I used it to deliver. Development continues across classroom operations and review features. My own teaching provides a concrete context for iteration; broader adoption and learning outcomes remain questions to investigate.
