01 / A familiar frustration

A useful answer. An unnecessary chore.

While organizing study material, I often moved rich responses from AI chats into Feishu—a Chinese collaboration workspace combining documents, knowledge, and office tools. The answer looked right in the chat. After pasting, formulas could turn into raw LaTeX, numbering could restart, and carefully structured content could become something I had to repair by hand.

That cleanup added no new understanding. It was the same mechanical work, repeated every time I saved an answer. I built FeasyPaste to make the handoff as ordinary as copying and pasting.

02 / Investigate before converting

What did “copy” actually carry?

A response can look the same while carrying different clipboard data. I built a clipboard inspector to examine available formats and their raw contents, then used format probes—headings, nested lists, code, and equations—to compare outputs across LLM sites with the representations Feishu produced and accepted.

The investigation moved the problem from “this paste looks wrong” to specific rules: which heading level to retain, where a list begins, how code language is represented, and where the formula source can be recovered.

03 / Rule-based translation

Translate structure, not just appearance.

Feishu’s official document model is built from blocks. A document has a root page; text, headings, lists, code, tables, and containers have their own identities and parent–child relationships. Looking like a formula or a nested list in HTML is only part of the handoff.

  1. 01 / READ

    Recover the source

    Read HTML and plain text. Recognize Markdown and site-specific representations; recover formula and code metadata where available.

  2. 02 / MAP

    Build semantic records

    Map content to text, heading, list, code, equation, and table structures. Retain sequence, nesting, and relationships.

  3. 03 / WRITE

    Prepare the paste

    Write Feishu-compatible HTML with its record data, alongside plain text, back to the clipboard.

Inside the clipboard HTML

A document, with its structure attached.

The converter embeds a docx/record payload in the HTML: record snapshots, block relationships, and selection information travel with the content.

<span
  data-lark-record-format="docx/record"
  data-lark-record-data="…">
</span>

The public documentation explains the block model. The clipboard record envelope comes from inspecting Feishu representations and implementing the converter; it is carried within standard text/html, alongside text/plain.

The rules run locally in the extension, without another LLM inference step. They preserve meaning in Feishu’s own forms: in the example above, a boxed sentence becomes a callout instead of imitating the chat’s exact styling.

04 / Interaction design

One small action between copy and paste.

The core interaction is a floating button on the AI page: copy a response, click to convert, then paste into Feishu. Loading, success, and error feedback make it clear when the clipboard is ready. The user stays in the task they were already doing.

THE DEFAULT PATH

Copy → button → paste

Keep the familiar copy operation; add a single conversion action.

FOR REPEATED USE

Select → shortcut → paste

Ctrl + Shift + F, or ⌘ + Shift + F on Mac. The shortcut can be customized in the popup.

FOR A WHOLE RESPONSE

Site copy → button → paste

Start with the AI site’s own copy button, then convert through the same floating control.

05 / Iteration in a changing environment

The source keeps changing. So do the rules.

The extension targets ChatGPT, Claude, Gemini, Grok, DeepSeek, Qwen, ChatGLM, and Doubao. These sites do not share one stable output format. Compatibility work therefore includes adapting the parser when their interfaces change.

1.0.1 / CODE BLOCKS

Follow the code, not one HTML tag.

ChatGPT’s CodeMirror-based viewer replaced the expected pre/code structure with cm-content and line breaks. I adapted the parser to this representation.

1.0.2 / INTERACTIVE MATH

Recover the formula behind the widget.

GenUI math widgets needed full response HTML captured through the copy-button workflow. The converter extracts formulas and removes slider, canvas, and axis UI that would otherwise become stray text.

These updates define the product’s practical boundary: preserve useful document content as the source evolves. Interactive widgets become document material; their interactivity does not transfer into Feishu.
